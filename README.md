# Find-thief V1.3 — 中国游客双功能版

**用户**：中国赴欧洲游客。**核心功能仅两项**：查找有证据的盗窃区域；无需注册地匿名提交具体丢失地点。

## 用户界面

- 采用独立纵向页面滚动；不再用 `100vh + overflow:hidden` 锁住手机屏幕。
- 地图在移动端 350px 高，默认可拖动与双指缩放；页面可从地图之外上下滚动。额外提供“地图拖动开/关”。
- 首次打开时三步使用引导，可再次打开。
- 仅显示官方事件聚合或人工核验且有有效许可的已发表区域；其他目的地显示“数据不足”，不把旅行防盗建议伪造为热点。
- 事件热度来自可追溯的类型、原始来源、统计期限、事件数量，不可解读为受害概率；匿名游客报告明确标记“自述，非警方认定”。
- 匿名投稿没有姓名、手机号、邮箱、登录。需要具体地址、时间、类别、简述，不公开原始地址；仅管理员核验后公开模糊区域。
- **线上接收当前保持关闭**：直到服务器专用密钥、管理员邀请/验证、运营主体合规及防刷服务完成。关闭时允许在浏览器保存草稿，明确标注“未上传”。

## 数据路线（不使用第三方盗窃事件API）

1. 首先获取允许复用的 **data.police.uk 开放CSV**（OGL v3.0）；脚本 `scripts/ingest_police_csv.py` 可离线生成约1公里事件格网，候选结果 **staging**，不自动发布。
2. 法国 SSMSI 市镇/省级公开统计、加泰罗尼亚 ICGC 警区统计应保留行政区边界、分类和日期，**不能当成具体的街道犯罪点**。
3. 对国内小红书/微博/马蜂窝/携程/微信公开内容与海外本地新闻、旅行社信息：建立 URL + 标题 + 时间 + 内容类别的线索登记；必须尊重 robots、登录边界、版权及个人信息，不进行未经授权的大规模复制。微博条款禁止未经许可自动化抓取。
4. 去重（地址、日期、叙述、来源）、证据审核、地图位置模糊化、定期更新。**未经核验的社交帖子永不直接成为高风险标记。**

## 数据库迁移

专用项目 `smwqqiebkdaheikihbrg`：运行 `supabase/20261014_analytics_evidence.sql`：
- `site_metrics_daily`: 仅日 × 事件类别 × 城市聚合值；无 IP、用户ID、会话。
- `source_leads`: 来源线索待审队列，默认不可公开。
- `evidence_areas`: 只有原始来源、时间、数量、许可证、管理员审核齐备才能 `published`。
- `count_site_metric` RPC 是 SECURITY INVOKER，执行仅授权 service_role。

服务端 `/api/metrics` 计量次数，包括页面打开、搜索、区域点击、上传流程等；管理员 `/api/admin` 登录后显示近30天聚合指标。计数可能含机器人触发，不代表独立访客。

## 配置及验收

Vercel 的 `SUPABASE_SECRET_KEY`（仅服务端）与 Supabase Auth 受邀且验证邮箱的管理员尚需完成。运营主体暂为 `private`，在实际收集游客上报前应满足适用的数据控制者告知要求。切勿把 secret key 传到聊天或前端。

检查手机 320/390、桌面1440 页面竖向滚动、地图拖动，地图点击选择事件点，信息不上传时被告知，仅已审核、允许复用证据展示等级。
